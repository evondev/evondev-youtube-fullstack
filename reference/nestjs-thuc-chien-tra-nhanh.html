🌉 Một câu tóm cả Module 2

Nest cho bạn bốn cái chốt để cắm code vào đúng chỗ trong vòng đời một request: middleware (trước mọi thứ) → pipe (lọc dữ liệu vào) → controller/service (làm việc) → filter (dọn khi hỏng). Học Nest thực chất là học việc nào cắm vào chốt nào.

🚨 Bẫy định tuyến — gặp một lần là nhớ đời

Nest khớp route theo THỨ TỰ KHAI BÁO, không theo độ cụ thể. Đặt @Get(':id') trước @Get('boom') thì :id nuốt luôn 'boom' → ParseIntPipe trả 400, và hàm kia không bao giờ chạy mà chẳng có lỗi nào báo.

Luật: route cụ thể luôn khai TRƯỚC route có tham số động. Cách tự kiểm: bảng route lúc khởi động in đúng thứ tự Nest sẽ khớp — nhìn là biết.

5. Validation — chặn ở biên

npm i class-validator class-transformer 
// dto/create-course.dto.ts — CLASS (interface không mang được decorator)
export class CreateCourseDto {
  // Dấu ! = giá trị do pipe đổ vào lúc chạy, không gán trong code.
  @IsString({ message: 'title must be a string' })
  @MinLength(3)                    title!: string;

  @IsIn(['beginner', 'advanced'])   level!: string;
  @IsInt() @Min(0)                price!: number;
}

// main.ts — bật MỘT LẦN, áp cho mọi route kể cả route viết sau
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,             // cắt trường không khai báo
  forbidNonWhitelisted: true,  // có trường lạ → 400 luôn
  transform: true,             // JSON thô → thể hiện class
}));
DecoratorKiểm gì
@IsString @IsInt @IsNumber @IsBooleankiểu cơ bản
@MinLength(n) @MaxLength(n)độ dài chuỗi
@Min(n) @Max(n)khoảng giá trị số
@IsIn([...]) @IsEnum(E)chỉ nhận giá trị liệt kê
@IsEmail @IsUrl @IsUUIDđịnh dạng
@IsOptional()vắng mặt thì bỏ qua các kiểm tra khác
@Transform(({value}) => value?.trim())xử lý TRƯỚC khi kiểm (cắt khoảng trắng)
⚠️ Hai điều dễ quên

1. @MinLength(3) đếm ký tự, không trim — chuỗi "   " vẫn lọt. Thêm @Transform để cắt trước.
2. whitelist không phải tuỳ chọn cho vui — không bật thì client gửi kèm {"isAdmin":true} sẽ lọt vào {...dto} và được lưu. Đó là lỗ hổng mass assignment. Nguyên tắc: liệt kê thứ ĐƯỢC PHÉP, đừng liệt kê thứ bị cấm.

6. Ném lỗi đúng cách

chỉ cần throw — Nest lo phần còn lại, tiến trình KHÔNG chết 
throw new BadRequestException('...');      // 400
throw new UnauthorizedException();          // 401 — bạn là ai?
throw new ForbiddenException();             // 403 — biết rồi, vẫn không cho
throw new NotFoundException('...');         // 404
throw new ConflictException('...');         // 409 — trùng dữ liệu
throw new UnprocessableEntityException();   // 422
filter chuẩn hoá — ý chính 
@Catch()   // để trống = bắt MỌI thứ, kể cả Error thường
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    // host = hộp ngữ cảnh chung (Nest còn chạy WS/gRPC), mở đúng ngăn HTTP:
    const ctx = host.switchToHttp();

    // Chia đôi thế giới lỗi — quyết định quan trọng nhất:
    //   HttpException = CÓ CHỦ Ý  -> nói thật cho client
    //   còn lại       = TAI NẠN   -> giấu chi tiết, chỉ ghi log
    const isHttpException = exception instanceof HttpException;
  }
}

// main.ts
app.useGlobalFilters(new AllExceptionsFilter());
🚨 Luật vàng về lỗi

4xx nói thật — 5xx giấu kín.
Lỗi client thì PHẢI nói rõ để họ sửa. Lỗi của mình thì chỉ trả "Internal server error", còn chi tiết ghi vào log — message mặc định của thư viện hay chứa tên bảng, đường dẫn file, chuỗi kết nối: bản đồ hệ thống trao tận tay kẻ tấn công.

Log cho MÌNH (đầy đủ) · Response cho NGƯỜI LẠ (chung chung).
